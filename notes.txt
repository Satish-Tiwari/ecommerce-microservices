### Maven & Common Library Notes

#### 1. Common Library Usage
- `common-lib` is a library, not a standalone service. Do not "run" it.
- To use changes in other services, install it to your local repo:
  `mvn clean install -pl common-lib -am`

#### 2. CI-Friendly Versioning (${revision})
- We use `${revision}` in the root POM for easy version management.
- **Problem**: Child modules installed with `${revision}` in their `pom.xml` cause resolution errors in consumer services.
- **Fix**: Added `flatten-maven-plugin` to the root POM. This resolves `${revision}` to the actual version (e.g., `1.0-SNAPSHOT`) before installation.
- **Flattened POM**: You might see a `.flattened-pom.xml` file in your directories. This is a temporary file generated by the plugin to be used for installation. You can ignore it or add it to `.gitignore`.

#### 3. Common Library Dependencies (Fixed)
- **RestAssured**: Required for API testing in `AbstractControllerIT`.
- **Spring Boot Testcontainers**: Required for `@ServiceConnection` in integration tests.
- **Parent Version**: Child modules must refer to the parent using `${revision}` to stay synchronized.

#### 4. Build Commands
- Build everything from root: `mvn clean install -DskipTests`
- Build specific service with its dependencies: `mvn clean package -pl <service-name> -am`
